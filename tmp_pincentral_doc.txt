2. Flujos
2.1. PIN
En la Figura 1 se ilustra el ﬂujo de operaciones durante un caso de obtención de PINs. Los pasos 1-3 son
opcionales.
Figura 1: Flujo recarga PINs
1. Un cliente tiene la intención de comprar o veriﬁcar disponibilidad de un producto.
2. El comercio envía una petición a PinCentral para veriﬁcar stock.
3. PinCentral responde el estado del Stock.
4. El cliente compra el producto.
5. El comercio solicita autorización de PINs. PinCentral descuenta saldo al comercio.
6. PinCentral responde con el identiﬁcador de la transacción.
7. El comercio solicita la captura de PINs utilizando el ID del pedido.
8. PinCentral responde con los PINs.
9. El comercio provee los PINs al cliente.

===== PAGE 4 =====
2.2. Recarga
En la Figura 2 se ilustra el ﬂujo de operaciones durante un caso de Recarga. Los pasos 1-3 son opcionales.
Figura 2: Flujo recarga
1. Un cliente tiene intención de veriﬁcar un usuario o comprar una recarga, proveendo datos correspon-
dientes.
2. El comercio solicita la validación de datos a PinCentral.
3. PinCentral responde a la validación de datos, eventualmente con información de la cuenta validada.
4. El cliente efectúa una compra de una recarga.
5. El comercio solicita la recarga a PinCentral.
6. PinCentral realiza la recarga y responde con el comprobante de recarga.
7. El comercio notiﬁca al cliente.

6. Seguridad
Las peticiones deberán contener los siguientes encabezados:
Request Header Valor
Authorization <api_key>:<hmac>
X-Date <date>
El campo hmac se calcula según el request utilizado, y se utiliza el algoritmo HMAC SHA256.
Se genera de la siguiente manera:
hmac_sha256(Verbo + ruta + X-Date + Cuerpo, api_secret)
La fecha a enviar debe ser la fecha de cuando se envía el request en el formato ISO 8601. Ejemplo: 2018-07-
12T13:46:28Z.

api_secret: test_secret
